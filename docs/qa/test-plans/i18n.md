## Cases

### TC-1 — Live locale switch re-renders every consumer (FR-I18N-01)

- **Requirement(s):** `FR-I18N-01` — "`LanguageContext` holds `locale` and a `t(key)`; `LanguageToggle` switches it live".
- **Preconditions:** A harness that wraps two or more `useI18n()` consumers plus a `<LanguageToggle />` in a single `<LanguageProvider>` (e.g. a temp `app/_i18n-harness/page.tsx`, deleted after).
- **Steps:**
  1. Render the harness at default locale; confirm consumers show EN prose (e.g. `t('addRoom')` → `Add room`, `t('title')` → `Apartment Module & Golden Ratio`).
  2. Click the `UA` segment of the toggle.
  3. Observe that **every** consumer updates in the same render pass — no reload, no stale EN text left behind.
  4. Click `EN` again and confirm a full revert.
- **Expected result:** All consumers re-render live on `setLocale`; `t()` is memoized on `[locale]` so identical text between switches is referentially stable but changes when locale changes. Locale lives only in `useState` (in-memory — BC-PRIVACY-01); a page reload returns to the default `en`.
- **Result:** `<pass | fail | blocked>` — `<note>`

### TC-2 — Automated core: parity, translator, never-translate (FR-I18N-02, FR-I18N-03) — AUTOMATED

- **Requirement(s):** `FR-I18N-02`, `FR-I18N-03`
- **Preconditions:** none (pure `node --test`).
- **Steps:**
  1. Run `node --test lib/i18n.test.ts` (or `npm test` for the full 34-case suite).
- **Expected result:** 9/9 pass, asserting: EN/UA key sets are identical in both directions (`missingKeys` == `[]`); every value is a non-empty string; sampled prose keys (`title`, `addRoom`, `errCeiling`, `comfortable`) genuinely differ between locales; `createTranslator` resolves known keys and falls back to the key (never `undefined`) on a miss; `CALC_LABELS` are exactly `['¼M','½M','M','1.5M','2M','3M','4M']` and appear as neither a key nor a value in either dictionary.
- **Result:** pass — 9/9 green at HEAD `6b620ac` (re-verified in this QA run).

### TC-3 — Toggle keyboard operability + `aria-pressed` / localized group label (FR-I18N-01, NFR-A11Y-02)

- **Requirement(s):** `FR-I18N-01` (accessibility of the switching control); touches `NFR-A11Y-02`.
- **Preconditions:** The harness from TC-1, with DevTools + a screen reader (VoiceOver/NVDA) available.
- **Steps:**
  1. Tab to the toggle; confirm a visible `:focus-visible` outline lands on each `<button>`.
  2. Confirm the active segment exposes `aria-pressed="true"` and the inactive one `aria-pressed="false"`; toggle and confirm the attribute follows the selection.
  3. Activate a segment with `Enter` and with `Space`; confirm both switch the locale (native `<button>` semantics).
  4. Inspect the wrapping `role="group"`; confirm its `aria-label` comes from `t('language')` — it reads the English label in EN and the Ukrainian label in UA (SC-001, resolved), not a hardcoded string.
- **Expected result:** The toggle is fully keyboard-operable, communicates the active locale via `aria-pressed`, and its group label is localized through the dictionary.
- **Result:** `<pass | fail | blocked>` — `<note>`

### TC-4 — No heavy i18n library; React-context + JSON architecture (TC-I18N-01)

- **Steps:**
  1. Run `git diff 9102c9a 6b620ac -- package.json package-lock.json` — confirm it is **empty** (no dependency added).
